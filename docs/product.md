# 产品与编辑流程

NannaNews 将来源收录、私有资料检索、编辑审核、刊发和历史刊物阅读分开处理。来源记录或模型结果都不等同于人工审核通过。

## 私有信息库

1. 只使用运营者有权收录的公开来源。不要上传私人消息、联系人清单、凭据或受限材料。
2. 通过来源收录或采集流程把内容保存到私有信息库。保留原始依据，并区分未读取、失败、未核验和已提取等状态。
3. 根据留存原文和图片逐项核对提取结果。没有依据的事实应保持未知，不把流畅的模型回答当作核验结论。
4. 在私有工作区撰写和修改。批准后的内容如有实质改动，必须重新审核。

可选的 `collect-worker` 与 Web 服务分开运行；只有运营者显式设置 `NANNA_COLLECTION_ENABLED` 才会启用。它只处理来源收录，不会批准或刊发内容，也不会生成刊物或发送通知。付费模型请求失败或结果不确定时不会自动重试。

## 审核与刊发

编辑根据已核对的依据准备内容，由另一位符合条件的审核人批准最终版本。批准后，编辑仍须单独设置刊发日期；草稿、未批准、未来刊发和已撤回的内容保持私有。修改已批准内容会撤销其批准和刊发状态，须重新审核。

匿名读者只能读取已刊发的公开内容。已登录的信息库和编辑页面仍是私有范围。不要把应用数据目录、数据库、上传文件或备份作为静态网站根目录。

本项目不发送电子邮件、不自动发布到群组，也不连接外部讲座同步服务。可配置的自有群组链接仅供读者打开，不是自动发送功能。

## 历史刊物读者端

历史刊物与当前编辑草稿、刊发内容分开保存。静态读者端由生成并审核过的公开白名单导出构建；它不连接私有数据库、Flask 应用、模型或采集进程。部署目录中的所有文件都可被匿名下载，因此不得导出完整数据库、凭据、编辑草稿、私有采集记录或备份。

更正来源、更新归档或生成新导出都不会自动发布。审核导出内容、构建静态读者端并明确发布站点是独立步骤。GitLab Pages 只提供可选静态托管，不是持续运行的 Python 后端。

## 与上游隔离

本实例使用自己的账号、数据目录、来源配置、模型端点和发布渠道。不要冒用或复用原 WebNews 运营者的身份、私有数据库、凭据、群组、邮箱或服务。保留 `LICENSE` 和根目录 `README.md` 中的上游署名与 GNU GPL v3 声明。
