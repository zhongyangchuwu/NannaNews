# 产品与编辑流程

NannaNews 将来源收录、私有资料检索、编辑审核、刊发和网页刊物阅读分开处理。来源记录或模型结果都不等同于人工审核通过。

## 私有信息库

1. 只使用运营者有权收录的公开来源。不要上传私人消息、联系人清单、凭据或受限材料。
2. 通过来源收录或采集流程把内容保存到私有信息库。保留原始依据，并区分未读取、失败、未核验和已提取等状态。
3. 根据留存原文和图片逐项核对提取结果。没有依据的事实应保持未知，不把流畅的模型回答当作核验结论。
4. 在私有工作区撰写和修改。批准后的内容如有实质改动，必须重新审核。

可选的 `collect-worker` 与 Web 服务分开运行；只有运营者显式设置 `NANNA_COLLECTION_ENABLED` 才会启用。它只处理来源收录，不会批准或刊发内容，也不会生成刊物或发送通知。付费模型请求失败或结果不确定时不会自动重试。

## 审核与刊发

编辑根据已核对的依据准备内容，由另一位符合条件的审核人批准最终版本。批准后，编辑仍须单独设置刊发日期；草稿、未批准、未来刊发和已撤回的内容保持私有。修改已批准内容会撤销其批准和刊发状态，须重新审核。

匿名读者只能读取已刊发的公开内容。已登录的信息库和编辑页面仍是私有范围。不要把应用数据目录、数据库、上传文件或备份作为静态网站根目录。

本项目不发送电子邮件、不自动发布到群组，也不连接外部讲座同步服务。可配置的自有群组链接仅供读者打开，不是自动发送功能。

## 网页刊物与历史阅读

网页刊物承接每期校园消息的阅读与分发。首页展示公开导出中最新一期，按校园动态、讲座、院级活动、社团活动和招聘等实际栏目编排；手机报头和横向栏目目录为正文让出首屏。卡片先展示标题、摘要及已核实的截止日期、活动日期，再展示时刻、地点、对象和参与要点；报名、申请日期保留各自含义，不自动改称截止时间。卡片不显示登刊日期；消息详情将刊载日期、其他刊载版本及来源日期放入默认折叠的参考区，按期阅读页面仍显示刊期日期和期号。风险信息统一收束为与“已对照原文”相邻的“阅读提醒”，点击进入详情查看完整原因，不在卡片堆叠警告段落。HTML 是正常原件，标为“网页原件（HTML）”，不会因为没有 PDF 报警；PDF 是可选原始附件，不是阅读前提。只有明确列为 PDF 却缺少资源时才提示文件不可用。消息原件按来源文档身份匹配，不拿同一天的其他 PDF 替代。

公开阅读页与私有控制台使用一致的系统字体、灰白底色、青色操作按钮和细边框，减少装饰与重复说明；手机端保留完整的操作名称和风险提示。

搜索框可选择本期（往期阅读时为这期）、当前活动或全部历史；在同一范围搜索时保留已有筛选，切换范围时不沿用不相容的筛选。按期阅读展示全部匹配消息，不截断为历史检索的一页。读完详情后点“返回阅读页”或使用浏览器返回，会恢复本标签页内的原消息、筛选及阅读位置；直接点首页导航则从页首开始。往期刊物按年份浏览，浏览器返回时保留所选年份。收藏只保存在本设备。

首页只读取期次元数据和最新一期的消息投影；打开往期时按需读取对应刊期，不在后台预取全部历史。期次目录只读取元数据，详情按需读取消息索引和详情分片。进入历史消息、当前活动或收藏时才加载全量目录；输入关键词后才加载浏览器搜索索引，搜索范围和历史记录不因首页减载而缩小。

筛选条件即时生效，手机筛选按钮显示已启用的条件数。“返回结果”只关闭筛选面板；“清除搜索与筛选”同时清除关键词和筛选条件，空结果页也提供此入口。

详情先展示摘要、实际日程和参与要点，再展示完整正文与海报。已核实且在引用文字中完整出现的参与链接可直接打开；否则提供原始通知或原刊入口，不猜测报名地址。已发布的人工修订优先展示人工填写的正文、字段、来源和公开核查说明，原刊与 AI 记录另列为只读参考；仍待核对的人工内容明确标注，不作为已确认活动。核查引句与原刊对照独立折叠，冲突、待核对、推定日期和已过节点等完整风险提示仍直接可见。

“当前活动”是独立日程页面，按北京时间的日历日期，将本页结果最近的已确认日程分为今天、本周（今天之后至周日）和稍后，保留总数与分页。只列入已对照原文或经人工核实、且仍有后续活动、报名或申请节点的消息；活动日期与截止日期分别展示，部分截止已过时仍会提醒，不被较晚的提交日程掩盖。报名／申请节点早于今天不自动等于报名已关闭。刊物总表中的索引日期不自动视为原文确认的活动或报名日期；日期未明、冲突、待核对及旧版未核验记录不进入该日程。AI 提取的日期类别与人工确认日期分别标明；当天活动可能已经结束，是否能报名须查看原始通知。

本期与单条消息均可分享。浏览器支持时调用系统分享；取消不显示成功，也不自动复制。否则复制标题、摘要和稳定链接；复制受限时提供可选中的文字供手动复制。分享链接不带个人筛选或返回位置，落地页提供对应消息或期次的标题、摘要和预览元数据。社交平台是否展示卡片取决于正式域名、公开访问及平台抓取策略，本地预览不代表微信等平台已验证。

历史刊物与当前编辑草稿分开保存。静态读者端由生成并审核过的公开白名单导出构建；它不连接私有数据库、Flask 应用、模型或采集进程，也不代替编辑审核界面。部署目录中的所有文件都可被匿名下载，因此不得导出完整数据库、凭据、编辑草稿、私有采集记录或备份。

更正来源、更新归档或生成新导出都不会自动发布。私有“人工核查”控制台直接只读查询统一的 SQLite 历史库，可登记新活动、筛选既有活动并追加修订；同一活动的全部刊载记录一起更新。活动身份不由标题或日期猜测。审查保留每次原始判断、错误、实际模型输入与响应及其来源，抓取内容另列；旧记录缺少的证据明确标为缺失。查看历史不会生成查询缓存、访问云端、重新取证或调用模型，执行新审查须单独授权来源访问和付费请求。

管理端保留各条刊载日期，可按精确期次标识打开对应原刊；独立活动、缺少可靠期次标识或无效的阅读页地址不生成猜测链接。“历史刊物附件”提供私有 PDF 元数据检索及校验下载，读取已登记的本地原件；云端备份独立执行，不另建存储。相同期号、日期或不同文件名不合并原件，文件名日期与正文日期不一致时明确保留差异。归档原刊不等于审核或发布其中的活动。

从核查队列进入活动、私有核查记录或来源详情后，返回队列会保留关键词、问题状态和页码。表单校验失败时保留本次输入并明确提示未保存。发布与付费核查提交后显示进行中提示，并阻止本页重复提交；确认授权仍须单独勾选。

保存与管理员发布是两个独立操作，操作者与逐字段差异只留在私有控制台，核查说明公开给读者；不覆盖原刊或原始 AI 证据。新活动发布后标为“独立收录”，提供审核过的来源，不伪造刊物、PDF 或未知日期；只有确认日期才进入当前日程。Git 中的白名单活动基本事实可独立构建读者端，私有请求、响应、原件和密钥不参与前端构建。该流程不替代当前编辑草稿的审批。配置与失败恢复见[人工核查网页活动](operations.md#人工核查网页活动)。GitLab Pages 只提供可选静态托管，不是持续运行的 Python 后端。

## 与上游隔离

本实例使用自己的账号、数据目录、来源配置、模型端点和发布渠道。不要冒用或复用原 WebNews 运营者的身份、私有数据库、凭据、群组、邮箱或服务。保留 `LICENSE` 和根目录 `README.md` 中的上游署名与 GNU GPL v3 声明。
